## 一、接口设计决策

1. **`GET /admin/members` 的 `status`：boolean → integer（0=禁用 1=正常 2=已注销）**。破坏性变更：管理后台需把 `status === true` 改成 `status === 1`，并新增"已注销"分支；同时新增 `status` 查询参数（0/1/2，空=全部）。
2. **恢复注销会员用独立接口 `POST /admin/members/{id}/restore`**（恢复时要校验手机号是否被占用，不复用 batch-status）。
3. **后台评论 `is_sensitive`/`hit_words`** 。
4. **注销放 auth 模块**（`/auth/cancel`，与 logout/change-phone 同族）。
5. **后台敏感词管理建新 tag「后台/敏感词管理」**。

## 二、新增接口速览

### 1. `POST /auth/cancel` — 注销账号（需登录）
请求 `{ phone, code, password }`：
- `phone`：当前账号绑定的手机号（发码时用同一个号，`scene=cancel-account`）
- `code`：短信验证码
- `password`：原密码

校验顺序即错误分支：**手机号格式 → 手机号≠当前账号绑定号 → 验证码错误/过期 → 密码错误**。
成功后账号置 `status=2`、清除登录 token，返回 `data.message = "注销成功"`；内容全部保留不删除。前端收到后清登录态跳登录页。

### 2. `GET /personal/member/{id}` — 用户详情（他人公开资料卡，需登录）
返回：`id`、`nickname`（打星后）、`avatar`、`bio`（打星后）、`bgImg`、`role`、`status`、`followCount`、`fansCount`、`publishCount`、`favoriteCount`、`leadingCount`、`isFollowed`（我是否关注 TA）、`isFollower`（TA 是否关注我）。
**不含 phone/password。** `status=2` 表示已注销（仍返回资料卡，前端标注"已注销"）。

### 3. 后台敏感词管理（新模块，需登录）
- `GET /admin/sensitive-words?page=&size=&keyword=`：分页列表，`keyword` 按词内容 LIKE 模糊搜索。返回 `list[{id, word, status, create_time}]`。
- `POST /admin/sensitive-words`：body `{ word }`，新增一个词（实时生效）。
- `DELETE /admin/sensitive-words/{id}`：删除一个词（实时生效）。

### 4. `POST /admin/members/{id}/restore` — 恢复已注销会员
把 `status=2` 恢复为 `status=1`。若该会员手机号已被其他在用账号占用 → 拒绝恢复并提示"手机号已被占用"。

## 三、原文档小改动清单

以下为**描述文字级**改动，schema 结构基本不变，可在原文档自行修改：

1. **`POST /auth/send-code`** — `scene` 字段的 `description` 改为：
   `login(登录)、register(注册)、reset-pwd(重置密码)、change-phone(更换手机号)、cancel-account(注销账号)`
2. **`POST /auth/login`** — `description` 追加：`已注销账号（status=2）密码/验证码两条路径均拒绝登录。`
3. **`POST /comments`** — 删除描述里 `评论内容含敏感词被拦截`、`命中 sensitive_word 返回 2001` 两句；追加：`命中敏感词不再拦截，内容存原文，响应 content 为打星后文本。`
4. **`GET /comments`** — `description` 追加：`content 为打星后文本。`（total 语义修正是后端内部修复，不在前端文档里通知）
5. **`GET /comments/replies/{id}`** — `description` 追加：`content 为打星后文本。`

> 涉及 schema 字段变更的（participants、is_sensitive/hit_words、status 三态、登录 status=2）已在新 OpenAPI JSON 中给全量定义，不必手改原文档。

## 四、内容

### 4.1 行为变更通知

1. **内容会显示 `***`**：评论、笔记、攻略、活动的标题/正文/简介/地点/交通方式，以及**昵称、个人简介**——凡用户输入内容都可能被打星。前端**不需要**自己处理：后端返回即打星后文本，前端也拿不到原文。
3. **`GET /personal/publish-activity` 新增 `participants` 字段**（`[{id, avatar, nickname, phone}]`），**全量返回**，前端弹窗内自行分页。**手机号仅活动领队（发布者本人）可见**，展示时加隐私提示"手机号仅供领队联系报名用户，请勿外泄"。
4. **新增 `GET /personal/member/{id}`**（他人公开资料卡）：关注列表、粉丝列表、评论区、活动报名人等所有带头像的地方，点头像跳用户详情页。
5. **新增注销功能**：个人中心加"注销账号"入口 → `POST /auth/cancel`（需当前绑定手机号 + 验证码 + 密码）。完整分步逻辑见「4.2-① 注销账号流程」，前端按它展示提示信息。
6. **已注销用户**：内容、评论、关注/粉丝列表、报名人等展示处标注"已注销"（灰化头像/昵称旁标）。点击其头像仍可进资料卡（资料卡标注已注销，不显示可操作项）。
7. **用户详情页资料卡字段**：头像/昵称/简介/背景图/关注数/粉丝数/发布数/收藏数/带队数/是否已关注/是否互关/是否已注销。

### 4.2 各流程逻辑说明

**① 注销账号流程（分步，前端按此做提示与错误分支）**

1. 用户点"注销账号" → 前端先弹**后果提示**："注销后账号将无法登录；账号无法使用，且不可自行恢复（需联系管理员/客服）。"
2. 前端展示当前绑定手机号（**打码**，如 `138****5678`）供确认 → 用户点"获取验证码" → `POST /auth/send-code`（`phone`=绑定手机号，`scene=cancel-account`）。
   - 后端逻辑与失败分支：格式错 →"手机号格式不正确"；手机号未注册 →"手机号未注册"；已注销 → 拒发。
3. 用户输入**验证码 + 原密码** → `POST /auth/cancel`（`{phone, code, password}`）。
   - 后端校验顺序即错误分支：手机号格式 → **手机号≠当前账号绑定号 →"手机号与当前账号不符"**（若用户改绑过手机号，用新号发码；这是防拿别人手机号的码注销自己）→ 验证码错/过期 →"验证码错误或已过期" → 密码错 →"密码错误"。
4. 全部通过 → 后端置 `status=2`、删除登录态 token → 返回"注销成功"。
5. 前端收到成功 → **清登录态、跳登录页**，提示"账号已注销"。
6. 注销之后：该手机号**无法再登录**，也**不能重新注册新账号**（注册查 phone 时已注销号仍算占用；除非后台恢复）。倒计时、输入框校验等交互与登录/注册保持一致。

**② 敏感词打星逻辑（发布时提示）**

- 用户发布评论/笔记/攻略/活动、修改昵称/简介时，内容命中敏感词 → 后端**不拦截**，照常发布成功，但前台展示时命中部分显示为**等长 `***`**。（后端实现）
- 前端可（自行决定）在发布成功后提示"内容含敏感词，部分内容已自动打码显示"；接口只返回打星后文本，前端拿不到原文。
- 后台管理看到原文 + "是否违规" + 命中词（评论）。

**③ 报名人手机号隐私**

- 仅"我发布的活动"里报名人列表带手机号（领队本人可见）。前端在手机号处提示："手机号仅供领队联系报名用户，请勿外泄"。
- 其他任何页面均不返回报名人手机号。

**④ 已注销用户展示**
- 关注/粉丝/评论/报名/用户详情等处遇到已注销用户，后端返回 `status=2`，前端标"已注销"（灰化头像/昵称旁角标），点击其头像仍可进资料卡（资料卡标注已注销，不显示可操作项）。
